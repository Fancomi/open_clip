**整行丢掉**（不是运行时截断）。运行时截断早就存在
（`src/open_clip/tokenizer.py:263-267`：保头、末位强写 EOT、绝不丢行），

## 1. 三个臂：把用户的两条要求拆成可归因的三点

宿主线选 **PCM w=0.2 d=32**（`longclip_01_pcm.md` 推荐的长文本配方，
七口径参照行齐全）。**不选 `gemma_dense` 单塔线**：那个模型是坏的
（IN-1k 0.96% / COCO i2t 7.70%），5 个口径上没有可测信号。

| 臂 | 数据 | 行数 | 窗口 | 超窗行怎么处理 | 对应用户要求 |
|---|---|---|---|---|---|
| **L0**（已有） | `clip_train_dual.tsv` | 2,006,804 | 256 | **丢整行** | 现状 |
| **L2**（新） | `clip_train_dual_full.tsv` | 2,894,191 | 256 | **截断** | 只要求 2 |
| **L1**（新，交付物） | `clip_train_dual_full.tsv` | 2,894,191 | **320** | **截断** | 要求 1 + 2 |

L0 = `logs/visreg_gemma_pcmw0.2d32_projective_E_0818_1857`，10 ep，seed 0。
L1 / L2 除数据与窗口外配方逐字相同（VISReg-E + Muon + SigLIP projective，
lr 3.4e-4，bs 512×8，10 ep，seed 0）。

三条轴：
- **A = L1 − L0**：用户两条要求合起来的端到端收益（生产决策数字）
- **B = L1 − L2**：**只有窗口在动**（数据、步数、seed 全部对齐）→ 最干净的一轴
- **C = L2 − L0**：只有"截断代替丢行"在动（窗口固定 256）
- 一致性检查：同口径下 `|A − (B + C)| ≤ 0.91`（= 2φ×√2，IN-1k）

## 2. 判据（三分带 + 符号，四个出口；写在跑之前）

### 轴 A：L1 vs L0，主口径 **IN-1k top1 全量**（2φ = 0.64）

定量预期从 §5.15 重复度消融外推：唯一数据减半 = IN-1k −3.2~−4.0（取 3.6）；
这里唯一数据 ×1.442 → log₂1.442 = 0.528 个"减半当量" → **预期 +1.9**。
（L1 还额外多 44.2% 优化步数，所以这是**下界**侧的锚。）

- **A1 达到或超过数据量外推**：Δ ≥ **+1.9** → 320+截断定为默认长文本配方，
  同时把 `dense_256` 系全部标记为"已过时口径"。
- **A2 显著为正但低于外推**：**+0.64 ≤ Δ < +1.9** → 采纳，但必须查
  是哪一族口径没跟上（截断产生的"半句话"是首要嫌疑）。
- **A3 不可分辨**：|Δ| < 0.64 → 那 30% 数据在这个规模上**看不出价值**。
  这本身是重要结论（与 §5.15"重复主导区"的结论相冲，需要单独写一节调和）。
- **A4 显著为负**：Δ ≤ **−0.64** → 截断引入的半句话伤害 > 多出的数据 →
  退到 `dense_320` 过滤版（只丢超 320 的 5.67%），并把"截断不是免费的"写成结论。

副口径（各自 2φ，方向一致性按"副口径自身 ≥2× 其地板且反向才算否决"，
见 `prereg-must-have-opposite-exit` 第四条）：k-NN bb、COCO i2t/t2i、DOCCI i2t/t2i。
**Urban（φ=2.36）明示排除否决权** —— 效应量大概率小于它的地板。

### 轴 B：L1 vs L2（窗口单独），主口径 **DOCCI t2i**（2φ = 2.88）

两个读法都报，**B-native 为主**：
- **B-native**：L1 按 320 分词 vs L2 按 256 分词 —— 各自按设计使用，生产数字。
- **B-matched**：两者都按 `--tok-context-length 256` 分词 —— 去掉"评测文本少被截"
  这一项，只留模型侧差异。（`encode_text` 是**切**位置编码，320 模型喂 256
  长 token 精确等价于 256 模型看同一段截到 256 的文本，无插值无损。）

- **B1 窗口本身有用**：Δ ≥ **+2.88** → 320 是对的，且值得单独评估 384
  （384 能把 token 保留率从 99.85% 推到 100.00%，代价约 +20% 文本塔计算）。
- **B2 不可分辨**：|Δ| < 2.88 → 收益全部来自"不丢行"；
  **`CTX_LEN=256 + 全量截断` 就够**，省掉 320 的 ~6~10% 训练时间。
  ⚠️ 即便判 B2 也**不改 320 的生产目标** —— B2 只说"在 CC3M 289 万这个规模上
  测不出"，不说"没有价值"；生产 dense 数据的目标窗口由用户定为 320。
- **B3 窗口有害**：Δ ≤ **−2.88** → 更长窗口摊薄位置编码/注意力反而变差，
  反直觉强结论，需要用 B-matched 复核后才敢写。

副口径：DOCCI i2t（2.94）、Urban 两向（仅 ≥4.72 才计）。

### 轴 C：L2 vs L0（截断代替丢行单独），主口径 **IN-1k top1**（2φ = 0.64）

- **C1 显著为正**：Δ ≥ +0.64 → 用户要求 2 单独就有价值。
- **C2 不可分辨**：|Δ| < 0.64。
- **C3 显著为负**：Δ ≤ −0.64 → 截到 256 的半句话有害 →
  此时 A 的任何正值都必须归给窗口，且 `dense_320` 过滤版应作为默认。

## 3. 登记在案的混淆项

1. **固定 10 epoch ⇒ L1/L2 比 L0 多 44.2% 样本，也多 44.2% 优化步数。**
   这项落在**轴 C 与轴 A** 上，**不落在轴 B**（B 的两臂步数、数据完全对齐）
   → 轴 B 是三条轴里唯一无此混淆的。步数匹配的 L0′（过滤数据跑 14.4 ep）
   要多花 5 小时，本轮**不做**，登记为后续项。
2. **多出来的 30% 不是随机抽样**，而是系统性地"被描述得更长"的那批图
   （超 256 行的平均长度 291 token）→ §5.15 的线性外推只是粗锚点，
   不能当精确预期。
3. **DOCCI 评测侧 3.2% 的 query 在 256 下触顶** → 320 读法下评测文本被截得更少。
   已由 `--tok-context-length 256` 的双读法拆开（B-matched）。
4. **所有地板都是借来的**（§5.19）→ 只给量级。本轮不安排同配方重复。
5. **`_trim_to_batch_max` 在三个臂上都基本失效**：per-GPU batch 512、
   L1 有 5.67% 的行 ≥320（L2/L0 更高），P(整个 batch 无触顶行) ≈ e⁻²⁹ ≈ 0
   → 每个 batch 实际都跑满窗口。无差异效应，但意味着 L1 的文本塔计算
   是 L2 的 320/256 = 1.25 倍。
6. **评测端口径**：五个评测入口已改为按 ckpt 的 `text.positional_embedding`
   自动探测 `context_length`（commit `7a166bd`）。此前写死 256 加载 320 ckpt
   会静默走 `resize_text_pos_embed` 把位置编码**插值**压回 256 —— 不报错、
   不 missing、指标只变差一点。管线漂移校验：CTRL ckpt 上 `eval_ovss` 复现
   VOC-20 mIoU=24.23 / aAcc=39.65（历史值）。
