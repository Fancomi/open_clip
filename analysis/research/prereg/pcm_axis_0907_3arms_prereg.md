## 0. 由来，以及为什么**不**跑我自己建议的 (W=0.5, p=0.1)

上一轮我盘完混合族（`pcm-region`）的 W × p 矩阵，结论是：
`W` 两端测过了（0.2 好、2.0 在两张表上都崩），中间档 0.5/1.0 没测但三条独立证据都指向
「不崩也不涨」；而 **`p` 这一维从来没动过，一直钉在 0.2**，且它是唯一直接作用在
「PCM × 高 W 的交互是负的」这个病根上的旋钮。当时我建议 **(W=0.5, p=0.1) 一个臂同时探两个方向**。

**这个建议我自己否掉了，理由是它违反本项目最硬的一条纪律：单变量。**
(W=0.5, p=0.1) 相对**任何**已有臂都同时动两项 —— 相对 C9F(W0.2,p0.2) 动 W 与 p，
相对 C11F(W2.0,p0.2) 也动 W 与 p。**它没有对照**，跑完只会得到一个孤点，
无论好坏都归因不到 W 还是 p 上。这正是 §5.35 那条教训的形状
（「A 与 B 的差来自旋钮 X」必须在 A、B 各自身上量过 X 的斜率），
也是「C11F vs C5 有 ≥3 个差异、禁止分解」这个死结的成因。

改成三个**各自单变量、各自有现成对照**的臂，它们正好把 (W=0.5, p=0.1) 夹在中间：

| 臂 | 配置 | 唯一变量 | 对照 |
|---|---|---|---|
| **P0** | W=0.2, **p=0** | PCM 分支关掉 | C9F 族（n=3） |
| **P1** | W=0.2, **p=0.1** | p 减半 | C9F 族（n=3） |
| **P2** | **W=2.0**, p=0.1 | p 减半 | C11F（n=1） |

P0 + P1 + C9F 给出 p 的三点曲线（0 / 0.1 / 0.2）；P2 直接问「减半 p 能不能把崩点推回来」。
若 P2 显示救回，(W=0.5, p=0.1) 就是自然的下一臂且届时**有 P2 当对照**；若 P2 没救回，
混合族的 `W` 轴就永久钉死在 0.2，中间档一并不排。

### 0.1 P0 是本批信息量最大的一臂：它是那个缺失的对照

§5.31 把「三损失配方带 −5.87 k-NN bb 图像塔代价」升级成 n=3 结论，而**这个坑至今无来源**：
`W` 已被 §5.35 否掉（抬 W 反而更差）、修丢行只值 +2.02（§5.32）、
候选**只剩 PCM 分支本身**。但这个候选一直没法测，因为 `C11F vs C5` 同时差三项
（PCM 分支 / `region_shared_scale` / 主分支 caption 来源）。

**P0 把这三项拆成两步**：
- `C9F − P0` = **只有 PCM 分支**在动（表、`region_shared_scale=True`、`caption_dense` 全部保留）；
- `P0 − C5` = 剩下的三项（`region_shared_scale` / caption 来源 / 表）的净效应。

⇒ P0 落在 C5 的 52.49 附近，那 −5.87 就归 PCM 分支，坑结案；
P0 仍停在 46.6 附近，则 **PCM 分支被排除**，坑归到 caption 来源（从未单独量过）。
两个出口都是结论，没有烂尾出口。

## 1. 代码前置：`--pcm-weight 0` 此前会崩，已修（两处，对历史所有臂是 no-op）

起训前查实：`p=0` **不是**「传个 0 就行」，旧代码会在第一个 batch 挂两次。

1. **解包元数不匹配** —— `CsvDataset` 只要 `csv_caption2_key` 命中列就吐 6 元组
   （`data.py:222`，与权重无关），而 `train.py:131` 的分支条件是 `is_region and is_pcm`
   （`pcm_weight > 0`）⇒ p=0 时走 5 元组分支 → `too many values to unpack (expected 5)`。
   **修法**：分支改按 **batch 的实际元数** 判（`len(batch) == 6`），并把结果记进 `_has_t2`
   供前向那一处复用。
2. **`tokenize2` 是 None** —— `tokenizer_secondary` 只在 `pcm_weight > 0` 时创建
   （`main.py:450`），p=0 时 `self.tokenize2 = None` → `'NoneType' object is not callable`。
   **修法**：`data.py` 里 `tokenizer2` 为 None 时回退主 tokenizer。两者在 `main.py` 里
   **构造参数逐位相同**（同 model、同 `context_length`）⇒ 对历史臂数值等价。

**两处都是严格 no-op**：至今每个臂都满足「配了 `caption2` ⟺ `pcm_weight > 0`」，
两个条件从未分离过。⚠️ 但按第 8 条静默失败模式（队列在跑时编辑 `src/` 只影响还没起的臂），
这里必须说明：**改动落在 `mon.sh` 的 C16 运行期间**，而 mon 三臂走 `region` 入口
（无 `caption2` 列、5 元组、`is_pcm=False`）⇒ 两处都不在它们的代码路径上，
**本批与 mon 批可比性不受影响**。已 CPU 实测验证：
`tokenize2 回退到主 tokenizer = True`、`batch 元数 = 6`、`train.py` 走 6 元组分支。

**p=0 时 PCM 是真的关掉而不是乘 0**：`main.py:323` 把 `pcm_dim` 置 0 →
`model.py:1057` 整段 PCM 前向跳过（短 caption **不过文本塔**、不走 PCA/SVD）→
`loss.py:1674` 不产生 `pcm_loss` 键。⇒ 损失项从 5 个变 4 个，且算力应明显回升（见 §5 闸 7）。

## 4. 判据

### 4.1 P0（p=0） vs C9F —— 主轴 k-NN backbone，门槛 0.28

Δ ≡ P0 − 46.62。**这一轴的地板极紧（0.14），点估计几乎肯定过线**，
所以真正的判读靠**幅度落在哪一档**，三档事前定死：

| 出口 | 条件 | 判读 |
|---|---|---|
| **Q1** | Δ ≥ **+4.0**（≥28×） | **PCM 分支就是那 −5.87 的主要来源**（回收 ≥68%）⇒ 坑结案；混合族「长文本 vs 图像塔」变成一个可定价的 trade-off，而不是无来源的结构性代价 |
| **Q2** | +0.28 ≤ Δ < +4.0 | **PCM 分支只解释一部分**（回收 5~68%）⇒ 按实测回收率写，剩余部分归到 caption 来源（未量过）；此时 **caption 来源单独测一臂**升为最高优先级 backlog |
| **Q3** | \|Δ\| < 0.28 | **PCM 分支被排除** ⇒ −5.87 全部归到 caption 来源 / `region_shared_scale`@W0.2 以外的项；这是「唯一剩下的候选也被否掉」，**必须写成独立结论，不许写成"没测出来"** |
| **Q4** | Δ ≤ **−0.28** | **反方向显著：关掉 PCM 反而图像塔更差** ⇒ PCM 分支对图像塔是净正项，那 −5.87 必须换整套解释。**升格为独立发现，不许折叠进 Q3** |

**协轴 1 = DOCCI i2t / t2i（长文本），门槛 5.20 / 3.08，三分带写全**：
`≤ −5.20/−3.08` 长文本代价（预期方向）/ `|Δ|` 内不可分辨 / `≥ +5.20/+3.08`
**反方向 ⇒ 升格为独立发现**（§5.34 那条规则的第九次兑现位）。
📌 这一轴本身是个独立产出：**它把混合族的长文本能力拆成「`caption_dense` 主分支」与「PCM 分支」两份**
—— C5（短 caption 主分支、无 PCM）只有 20.03/20.05，C9F 是 73.13/75.57，
P0 落在中间的位置就是两份的分配比例。**这是全项目第一次能给这个拆分定量。**

**协轴 2 = VOC penult mIoU（局部），门槛 6.24，三分带同样写全。**
先验：区域分支一字未动 ⇒ 押不可分辨；若显著变化，说明 PCM 分支对局部有独立作用（此前只在 §5.26 的
「G→C9」比较里见过，且那次无判决权）。

### 4.2 P1（p=0.1） vs C9F —— 同一主轴，门槛 0.28

Δ ≡ P1 − 46.62。四档与 §4.1 逐字相同（R1/R2/R3/R4 = Q1/Q2/Q3/Q4 的形状），
**但 P1 的真正价值不在自己这个 Δ，而在它与 P0 拼出的三点曲线**，所以判决要多写一条形状判据：

| 出口 | 条件（以 P0 的 Δ₀ 为标度） | 判读 |
|---|---|---|
| **S-lin** | P1 的 Δ₁ 落在 [0.35, 0.65]·Δ₀ | **p 对图像塔近似线性** ⇒ 代价可按剂量定价，`p` 成为一个连续可调旋钮 |
| **S-sat** | Δ₁ > 0.65·Δ₀（减半 p 就拿回大半） | **p 的代价在 [0.1,0.2] 已接近饱和** ⇒ **p=0.1 是免费午餐候选**：留住大部分长文本、退掉大部分图像塔代价。若同时 DOCCI 两轴在门槛内不可分辨，**这就是本批最有价值的产出**，直接进选型表 |
| **S-thr** | Δ₁ < 0.35·Δ₀（减半 p 几乎没用） | **代价是阈值型/凸的** ⇒ 只要 PCM 在场就付掉大部分代价，`p` 不是有用旋钮 ⇒ **混合族的图像塔代价只能靠结构改动消**，`p` 轴一并关闭 |
| **S-non** | Δ₁ 与 Δ₀ 反号且 \|Δ₁\| ≥ 0.28 | **非单调** ⇒ 三点不构成曲线，不许拟合任何剂量模型；按单点各自报，并记为「p 轴形状未知」 |

⚠️ **Δ₀ < 0.28（即 P0 判 Q3/Q4）时 §4.2 这张形状表整体作废** —— 分母不显著，比值无意义。
此时 P1 只按自己的四档单独判，且必须写明「P0 未给出可用标度 ⇒ p 轴形状本批判不了」。
📌 这条事前写下来是因为它正是 §5.29 那个「一致性检查其实是代数恒等式」的近亲：
**任何以另一臂的 Δ 作分母的判据，都要先给分母配一个显著性前提。**

**协轴 = DOCCI i2t / t2i，门槛 5.20 / 3.08，三分带写全（含反方向升格出口）。**
先验：长文本能力主要由 `caption_dense` 主分支扛（P0 会直接量出这个比例），
p 减半**押不可分辨**；若 DOCCI 显著掉而 k-NN 显著涨，那就是一条干净的 trade-off 定价曲线，
**这是本批第二个可能直接进选型表的产出**。

### 4.3 P2（W=2.0, p=0.1） vs C11F —— 主轴换成 VOC penult mIoU，门槛 6.24

⚠️ **两侧都是 n=1 ⇒ 本节一切结论写「seed 0 上」，不许写成族结论。**
Δ ≡ P2 − 31.40（C11F 实标）。

| 出口 | 条件 | 判读 |
|---|---|---|
| **T1** | Δ ≥ **+15.0**（≥2.4×门槛，且 P2 ≥ 46.4 ≈ 追平 C5/C9F 量级） | **减半 p 把崩点推回来了** ⇒ §5.35「PCM × 高 W 是负交互」定量化为「交互强度 ∝ p」⇒ **混合族的 `W` 轴重新打开**，`(W=0.5, p=0.1)`（用户原建议）立刻排为下一臂，且**届时以 P2 为对照、单变量成立** |
| **T2** | +6.24 ≤ Δ < +15.0 | **部分救回** ⇒ 交互项确实随 p 减弱但不足以让 W=2.0 可用；`W` 轴仍关闭，但「p 是交互项的调节旋钮」成立 ⇒ 下一步该动的是 p 而不是 W |
| **T3** | \|Δ\| < 6.24 | **减半 p 救不回来** ⇒ **混合族 `W` 轴永久钉死在 0.2，中间档 0.5/1.0 一并不排**（§0 已事前承诺）；且说明那个负交互**不是 PCM 剂量的函数**，只要 PCM 在场就发生 ⇒ 与 S-thr 互为独立佐证 |
| **T4** | Δ ≤ **−6.24** | **减半 p 反而更差** ⇒ 交互项符号读反了，**升格为独立发现**，必须重写 §5.35 的机制表述，不许折叠进 T3 |

**协轴 1 = k-NN backbone，参照 C11F 的 46.00，门槛 0.28（借 C9F 族地板，与 W 无关的口径）。**
三分带写全。📌 这一轴与 §4.1/§4.2 合起来回答一个独立问题：
**p 对图像塔的效应是否依赖 W** —— 若 (P1 − C9F) 与 (P2 − C11F) 同号同量级，
则「p 的图像塔代价与 W 可分离（加性）」；若两者反号，那就是**又一个交互项**，
按 §5.35 的教训**必须在两个 W 上都量过才准谈迁移**，本批正好是这个规则的第一次主动兑现
（而不是事后补救）。

**协轴 2 = DOCCI i2t / t2i，门槛 5.20 / 3.08。** ⚠️ C11F 的 DOCCI 是 §5.35 的推导值
（≈72.86 / 73.66），**判决时必须回 §5.35 正文取原始数**；若正文只有 Δ 没有绝对值，
则本协轴降为「只记录、无判决权」，不许拿推导值当参照点判显著性。
📌 这条限制事前写下，正是 §5.31 那次「预登记里的算术自己算错」的防线。
