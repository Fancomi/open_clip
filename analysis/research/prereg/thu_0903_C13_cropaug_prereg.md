# 预登记：C13 —— 区域监督 + 随机裁剪（框随裁剪同步变换，删框判据放宽到「clip + 保留面积 ≥ 0.8」）

写于 2026-09-03 14:2x，**在 C13 起训之前**（当前 GPU 在跑 C12，其后 C11F，C13 排第三，
预计 09-04 05:00 左右起训）。落盘 commit 见 git log。

## 1. 这一臂在问什么

区域监督从第一天起就被迫用 `--image-resize-only`（框坐标是相对原图归一化的，
默认 `RandomResizedCrop` 会让坐标失效）。而关掉随机裁剪本身是有代价的：
**gt 族实测 COCO i2t −1.70 / IN-1k −0.70**（`gt_s1` 有裁剪 23.16/22.95 vs `A'` 无裁剪
21.46/22.25，同 commit，均超当时的 2σ）。§5.2 记下这笔代价后就一直没填。

08-24 试过一次（H 组 `regw0.2k12-cropaug_0824_1706`，`RandomResizedCropWithBoxes`）判有害，
但那次的归因是错的：当时写「保框约束削弱了增强」，08-26 复查发现 **H 用的
`scale=(0.9,1.0)` 与 `gt_base` 完全相同** —— 增强强度一点没削弱，
真正的差别是**删框判据**：H 用「完全包含」（框整体落在裁剪区内才留）。

本臂 = C5 唯一换图像变换，并把删框判据从「完全包含」换成
**「clip 到画面内 + 保留面积/原面积 ≥ 0.8」**。实测（`clip_train_region.tsv`，
3000 图 / 20138 框，K=12，`scale=(0.9,1.0)`，`ratio=(3/4,4/3)`）：

| 判据 | 丢框率 | 零框图 | 平均留框/图 |
|---|---|---|---|
| 无裁剪（C5 现状） | 0 | 0 | 6.71 |
| 完全包含（H 组用的） | **26.2%** | 6.0% | 4.95 |
| **clip + 面积 ≥ 0.8（本臂）** | **6.9%** | 1.7% | **6.25** |
| clip + 面积 ≥ 0.6 | 1.8% | 0.8% | 6.59 |

⚠️ 与 09-02 那次口头记的「28.7% → 1.2%」不同：**1.2% 实际对应 thr=0.5，不是 0.8**
（本次用实现本身重测，见 `/tmp/verify_keep_area.py`）。写结论时用上表这一列。

## 4. 主轴与出口（起训前定死）

**主轴 M = k-NN backbone**（纯图像口径；随机裁剪的收益本质是图像塔泛化，
且 H 组当年报的伤害也在这根轴上）。参照点：**C5 两 seed 均值 52.49**。

| 出口 | 条件 | 读作 |
|---|---|---|
| **D1** | M ≥ 53.09（Δ ≥ +0.60） | **§5.2 那笔 resize-only 代价可以填回来** → 立刻排 seed 1，并考虑把 `crop_aug + thr=0.8` 定为区域族生产默认 |
| **D2** | 51.89 < M < 53.09（\|Δ\| < 0.60） | **不可分辨** → 在区域监督在场时随机裁剪的正则化收益测不出来 → 该轴关闭，§5.2 的代价标注为「只在无区域损失的 gt 族观察到」 |
| **D3** | 50.0 ≤ M ≤ 51.89 | 有害但温和 → **H 组的判决在丢框率降到 6.9% 后仍复现** ⇒ 伤害不是丢框造成的，而是裁剪本身与区域监督不兼容 |
| **D4** | M < 50.0 | 强有害（≥8×）→ 同 D3 的读法但升级；下一步查几何一致性（`roi_align` 在 aspect 被拉伸后的框上是否还对得上） |

**协轴 L = VOC penult mIoU**（判「丢掉 6.9% 框 + 改几何」有没有伤局部）。
参照点：**C5 两 seed 均值 46.70**。

| 出口 | 条件 | 读作 |
|---|---|---|
| **E1** | L ≥ 40.64（\|Δ\| < 6.06） | 局部未受损 |
| **E2** | L < 40.64 | 局部受损 → 报 (46.70−L)/3.03，并把「区域监督与随机裁剪不可兼得」写进选型表 |

⚠️ **四种组合都要能读**：
- D1 + E1 = **纯赚** → 区域族生产配方改带 crop-aug（须先补 seed 1）；
- D1 + E2 = 全局赚局部亏 → 又一个「只看全局会把局部崩塌写成成功」的候选，按 §5.16 铁律**以局部为准不上线**；
- D2/D3/D4 + E1 = 亏在全局 → 干净地关掉这条轴（本项目第一次有「增强 × 区域损失」的净效应数）；
- D3/D4 + E2 = 两边都亏 → `region_crop_aug` 整条功能标记为「不要再试」，连 thr=0.6 也不排。

## 5. 副判据（各自独立，不参与主判）

1. **事前方向预测（这才是本臂的靶子）**：§5.2 的代价是 COCO i2t −1.70 / IN-1k −0.70
   → 若收益真能填回来，应看到 **COCO i2t ≥ +1.50（2× 借来地板）与 IN-1k ≥ +0.64**。
   两根都过 = D1 的机制解释成立；**主轴过而这两根不过 → 只能写「图像塔变好但来源不明」**。
2. **平均留框数**：`out.log` 必须出现
   `删框判据=clip + 保留面积 ≥ 0.8`；且 `params.txt` 里 `region_keep_area_thr: 0.8`、
   `region_crop_aug: True`、`image_resize_only: False`。缺任一 → 本臂作废（这是
   `MAX_REGION` / `--train-num-samples` 两次静默 no-op 的教训）。
3. **有效吞吐**（累计样本 ÷ 墙钟）：C5 族 ~1444。`resized_crop` 比 `Resize` 略贵，
   预期落在 1350–1460；低于 1300 要在结论里标注「本臂另含 ≥10% 算力代价」。
4. **长文本**：DOCCI 相对 C5 两 seed 值，门槛 5.94/8.20 —— 这一族 R@1 只 ~19%，
   §5.22 已定这里功效很低 → **只记录，不判**。
5. **ADE penult aAcc**：MIL 族此轴 2φ=0.28 极灵敏（§5.25 每跳 15~18×）
   → |Δ| ≥ 0.56 就报；⚠️ 但**不许**把它当主轴的替代（§5.30 已定灵敏度不跨旋钮外推）。

## 7. 押注（写下来，但不参与判决）

押 **D2 + E1（不可分辨）**。理由三条：(a) §5.2 那 −1.70/−0.70 是在**没有区域损失**的
gt 族上测的，而 W=2.0 的区域损失本身就是很强的正则（§5.15 已证它部分替代唯一数据多样性）
→ 两种正则很可能重叠；(b) 那个数用的是当时的旧口径（k-NN 子集地板 0.78 已作废），
量级本身不可靠；(c) 丢框 6.9% 对应平均留框 6.71→6.25，只掉 6.8% 的区域样本，
按 §5.15 的样本效率曲线折算不到 0.3 点。

⚠️ 若结果是 **D1**（真能填回来），那说明「resize-only 是区域监督的固有代价」这条
写了一个月的限定条件是错的，**按 §4 直写并立刻排 seed 1**，不许事后把它说成「早就想到」。
