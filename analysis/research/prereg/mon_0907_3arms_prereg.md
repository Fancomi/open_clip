## 0. 本批的由来：09-06 深夜查出一个 crop-aug 的短语错配 bug

写 Task #36 的选框代码时顺手读了 `RandomResizedCropWithBoxes`，发现删框路径有 bug：

```python
kept = b[keep]          # 保留的框被**压到前面**
...
region_texts = self.tokenize(phrases[:n_valid] + [""] * pad2)   # 短语却是「取前 n 个」
```

只要被丢的框不在末尾，从它往后每个 slot 的短语都错位一格。
框按面积降序 ⇒ 大框在前、也最容易被裁出画面 ⇒ **错配偏向从开头就发生，影响最大**。

CPU 实测（`clip_train_region.tsv` 的 1/100 代表性切片 = 2 万图，`/tmp/measure_misalign.py`）：

| 臂 | thr | 丢框率 | 有丢框的图 | 错配短语的图 | **保留框中错配比例** |
|---|---|---|---|---|---|
| C15 | 0.0（完全包含） | 39.92% | 73.59% | 65.34% | **53.95%** |
| C13/C13s1 | 0.8 | 1.37% | 8.46% | 6.52% | **2.41%** |
| C14 | 0.6 | 0.23% | 1.52% | 1.03% | **0.27%** |

⚠️ 这也顺手兑掉了一笔欠账：`--region-keep-area-thr` 的 help 与
`sun_0906_3arms_prereg.md` §1 里那组丢框率（26.2% / 6.9% / 1.8%）测在
`clip_train_region_k24.tsv` 的**前 3000 行**上，而那一段每图只有 8.29 个候选框、
全表是 18.71（>K 的行 23.9% vs 全表 77.5%）—— **不具代表性**，已在 docstring 里标注并改用上表。

### 0.1 对已落地/在跑的四个 crop-aug 臂怎么处置

| 臂 | 错配比例 | 处置 |
|---|---|---|
| C13（§5.34 已判，VOC penult +7.42 = 2.45×） | 2.41% | **结论维持**，加一条限定「带 2.4% 短语错配」；错配是噪声 ⇒ 真实效应 ≥ 实测 |
| C13s1（09-06 22:02 起，在跑） | 2.41% | **不 kill**，与 C13 同一代码路径 ⇒ 仍是干净的 seed 复现 |
| C14（thr=0.6） | 0.27% | **不 kill**，近乎无污染 |
| C15（thr=0.0） | **53.95%** | **不 kill** —— 它恰好逐位复刻 08-24 H 组的代码路径，是「H 组当年到底为什么判 crop-aug 有害」的历史复现臂；但它**分不开**「丢掉 40% 框」与「一半配对错了」两件事 → 由本批 C16 拆 |

**修法用默认关的开关 `--region-crop-fix-align`，不是无条件改。**
理由是本项目的全部结论依赖同配方逐位可比：若无条件修，C14/C15 会在队列中途悄悄换代码，
与已完成的 C13/C13s1 就变成两变量比较，整批作废。
📌 **这本身是一条新的静默失败模式：队列在跑时编辑 `src/` 会只影响还没起的臂。**

## 1. 三臂配置

公共底：`bash scripts/train/visreg.sh region`，即 C5 配方
（`grid=2 + agg=mil`，`REGION_WEIGHT=2.0`，`MAX_REGION=12`，`region_gather=local`，
`region_cc_weight=0.1`，`region_shared_scale=False`，EPOCHS=10）。

| 臂 | 表 | 唯一变量 | 其余 |
|---|---|---|---|
| **C5s2** | `clip_train_region.tsv` | `--seed 2` | 与 C5 s0/s1 **逐位相同**（不传 chunk、不传 select、resize-only） |
| **C16** | `clip_train_region.tsv` | `--region-crop-fix-align` | 其余与 **C15 完全相同**（crop-aug、`thr=0.0`、seed 0、不传 chunk） |
| **F3** | `clip_train_region_k24.tsv` | `--region-select random-epoch` | `MAX_REGION=12`、`--region-text-chunk 2048`、seed 0、resize-only |

三个「不是变量」的点，事前声明：

1. **F3 的对照是 C5（n=3，本批第一臂落地后重算）**，不需要专门跑一个 `order` 臂 ——
   `build_region_tsv.py` 在截断前按面积降序排（92 行 `items.sort(key=lambda t: -t[0])`），
   所以 k24 表的前 12 项必然等于 k12 表的全部项。**实测 200,000 行对齐比较 mismatch = 0**
   ⇒ `--region-select order` 跑 k24 表 = 逐位复刻 C5，**白省一个臂位**。
2. **`--region-text-chunk 2048` 记为非变量**：CPU 实测与整块前向 max|Δ| = 1.0e-7
   （与 trim-to-max 自身的 1e-7 同量级），沿用 §5.33 里 C12 vs C5 的同一先例。
   F3 需要它是因为 random-epoch 会随机抽到长尾短语，而显存峰值由 batch 内最长那条决定。
3. **C16 不传 chunk**，因为 C15 没传 —— 单变量优先于省心。

## 2. 为什么是这三个

- **C5s2 排第一，是基建**：本批与后续每一个臂的判据分母都是 MIL 族地板，而它现在只有 n=2。
  §5.31 实测 **n=2 的 φ 系统性偏小，四个口径低估 3.4~12.2 倍，13 个口径里没有一个偏大**
  ⇒ 拿 n=2 地板判出来的「显著」有单向的高估风险。先把它补成 n=3，再判后两臂。
- **C16 是信息量最大的一臂**：54% → 0% 的配对错误率，是全项目单次改动里最大的干预幅度，
  且它一次性回答三个挂着的问题（08-24 H 组判决的真因、区域监督对配对噪声的鲁棒性、
  「丢框率」到底是不是 `thr` 的有效作用通道）。
- **F3 是 Task #36 三个候选里先验最强的一个**。放弃 F2（`random`，「哪 12 个」）
  与 F4（`dedup`，去重）：§5.33 已判 K=12→24 既没用也没害 ⇒「换哪些框」这一轴先验低；
  F3 换的是**每 epoch 都不同的框**，性质上属于「零算力增加唯一监督」，与前者不是一件事。

## 3. 判据

### 3.0 参照值（起训前抄下，判决时不许改）

C5 两 seed 均值：VOC penult mIoU **46.70** / last **55.40**、ADE penult mIoU **5.71** /
aAcc **15.66**、k-NN bb **52.49** / proj、IN-1k **33.59**、COCO **33.85/24.47**、
DOCCI **20.03/20.05**。

MIL 族地板（表内列的是 2φ，**门槛 = 2 × 列值**）：
k-NN bb 0.30 → 门槛 **0.60**；proj 0.29 → 0.58；IN-1k 0.32 → 0.64；
VOC penult mIoU 3.03 → **6.06**；VOC last 4.30 → 8.60；
ADE penult mIoU 1.64 → 3.28；ADE penult aAcc 0.28 → 0.56；
COCO 0.75/1.13 → 1.50/2.26；DOCCI 2.97/4.10 → 5.94/8.20。

⚠️ **C5s2 落地后这一列全部按 n=3 重算（2σ̂，ddof=1），后两臂用新列判。**
新旧列都要写进结论页。这条写在这里就是为了不让门槛在有数之后被挑：
**重算规则事前定死，重算结果本身允许把门槛抬高或压低。**

### 3.1 C5s2 —— 无判决，只标地板

它不产生「有效/无效」结论，只有形态闸与地板产出：

- **形态签名**（判它有没有落进别的盆地，落了则不能进地板计算）：
  四个（epoch × 读出）无一 `last < penult`、VOC last 在 50 量级、四轴 ep5→ep10 全升。
- 产出：13 个口径的 n=3 φ = 2σ̂(ddof=1)。
- **失效模式（事前写）**：若三 seed 极差 > 2 × 现门槛，**只当「n=2 地板标小了」记录，不当异常臂**
  —— 这是 §5.31 在 C9Fs2 上原封不动兑现过一次的条款。
- 副产物：VOC penult 的 n=3 均值将替换选型表里 C5 的代表值。

### 3.2 C16（`thr=0.0` + 修配对） vs C15（`thr=0.0` 原样）

**唯一变量 = 短语配对是否正确**（54% → 0%）。
主轴 **VOC penult mIoU**（区域监督直接作用的读出层，配对错误最该伤它），
门槛 = 2 × 2φ_MIL = **6.06**（C5s2 落地后按 n=3 重算）。
Δ ≡ C16 − C15。

| 出口 | 条件 | 判读 |
|---|---|---|
| **G1** | Δ ≥ +6.06 | **错配是主因** ⇒「完全包含」这个删框判据本身没错，08-24 H 组「crop-aug 有害」的真因是这个 bug；§5.34 对 H 的归因要第三次改写 |
| **G2** | \|Δ\| < 6.06 | **不可分辨** ⇒ 区域监督对 54% 的配对噪声鲁棒（这本身是个大结论，不是烂尾）；H 组的害归给「丢掉 40% 的框」 |
| **G3** | Δ ≤ −6.06 | **反方向显著** ⇒ 修对配对反而更差，需要新机制（如错配起了标签平滑作用）。**升格为独立发现，不许折叠进 G2** |

协轴 **k-NN bb**（图像塔），门槛 0.60，**三分带同样写全**：
`≥+0.60` 图像塔也受益 / `<0.60` 不可分辨 / `≤−0.60` **反方向 ⇒ 升格为独立发现**
（§5.34 那条规则的第八次兑现位；上一次正是因为协轴只写了单边，
一个 2.45× 的正信号差点被机械归档成「未受损」）。

**第二个比较（无判决权，只记录）**：C16 vs C13（thr=0.8，2.41% 错配）。
若 C16 ≈ C13，则「丢框率」这个通道整条关闭 —— 丢 40% 框与丢 1.4% 框在配对都正确时等价，
`thr` 就不是旋钮。若 C16 明显低于 C13，则框数量确实值钱。
两变量（thr 与丢框数同时变），所以只记不判。

### 3.3 F3（`random-epoch`） vs C5（`order`，n=3）

**唯一变量 = 每 epoch 是否重挑区域框。**
唯一监督量：`order` 的 top-12 每图 10.92 框 / 9.35 唯一短语；
全部候选 18.71 框 / 15.09 唯一短语 ⇒ **10 个 epoch 累计用到的唯一短语 +71%，图像集合不变、算力不变**
（CPU 实测 3000 图：`order` 十轮只用到 24872 个候选里的 20138 个 = 81.0%，
`random-epoch` 十轮用到 24869 = **100.0%**）。

主轴 **k-NN bb**（§5.35 铁律：结论落在图像塔质量上一律直接报 k-NN，不用 IN-1k 代理），
门槛 0.60。Δ ≡ F3 − C5(n=3 均值)。

| 出口 | 条件 | 判读 |
|---|---|---|
| **F3a** | Δ ≥ +0.60 | 每 epoch 重挑有效 ⇒ 零算力拿到唯一监督增量，进生产默认 |
| **F3b** | \|Δ\| < 0.60 | 不可分辨 ⇒ 连同 §5.33 的 K2，**选框/框数这一整轴关闭**，F2/F4 不排 |
| **F3c** | Δ ≤ −0.60 | **反方向显著** ⇒「同一图配同一组框」的稳定性本身有价值 ⇒ 独立发现 |

协轴 **VOC penult mIoU**，门槛 6.06，同样三分带写全（含反方向升格出口）。

**校准先验（事前算，允许被打脸）**：§5.29 修丢行 bug 给了 +44% 唯一**图像** → k-NN bb **+2.02**。
F3 给的是 +71% 唯一**短语**、图像一张没多。短语只喂区域分支（占总损失约 2/3），
且区域短语的信息密度远低于整条 caption ⇒ 打折后预期 **+0.6 ~ +1.5（1~2.5× 门槛）**。
**押 F3a 弱成立**（押注写下来，但不参与判决）。

**反方向的顾虑也写下来**：`random-epoch` 让同一张图在不同 epoch 见到不同的框，
相当于给区域目标加了噪声/降低了每个（图, 框）对的重复次数。
§5.15 的 H3（区域监督部分替代唯一数据多样性）在这里方向不明 —— 它说的是
「区域监督能顶一部分唯一数据」，推不出「多样化区域框一定更好」
（📌 §5.29 已记过同型教训：「A 能替代 B」推不出「有 A 时 B 更不值钱」）。
