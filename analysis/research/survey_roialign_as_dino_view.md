# 调研：用特征图 ROIAlign 取代 DINO 的像素 crop（起实验之前）

> 2026-09-02。用户提问：FineCLIP / FG-CLIP 用 patch 特征图取 ROIAlign 而不是 crop 后重新过
> vision tower；能不能把 DINO 的大小 crop 也换成「同一次前向的特征图 ROI」？预期明显提速，
> 但效果不确定 → **先查同型方案有没有人做过**。
>
> 本页只回答「有没有人做过、做出来什么数字」，不做设计。设计与判据在
> `prereg/`（Task #37，未起）。所有 arXiv 编号都核对过，凡查不到的一律写「未找到」，
> 不写猜测编号。

## 一句话结论

**「两侧都从同一次前向的特征图取视图」这个形式，整个文献里没有人做过。**
所有用特征图 ROI 做自监督的方法（DetCon / ODIN / SoCo / InsLoc / UniVIP / SlotCon /
CrOC / CrIBo / Leopart / ReSim / STiCA）**都至少保留两路独立增强的像素视图**——
ROI 只用来在两路之间**配对**，从不用来**造出第二路**。
→ 这条路不是没人想到，是**大家都在源头上避开了**（怕塌，见下面的泄漏问题）。
所以这是一个**真的新实验点**，不是复现；相应地，风险也没人替我们验过。

## 最近的先例：CLIPSelf（arXiv 2310.01403，ICLR 2024 Spotlight）

方向**正好相反**：它用**真 crop 当老师**去教**特征图 ROI 当学生**。也就是说，
学界的共识是「特征图 ROI 是差的那一侧、需要被 crop 教」，而我们想让它当唯一的一侧。

| 表 | 内容 | 数字 |
|---|---|---|
| A2 | OpenAI ViT-B/16，真 crop vs 稠密 ROI（region 分类 Top1/Top5） | **63.8/83.7 vs 29.3/51.6**（−34.5） |
| 7 | EVA ViT-B/16 稠密 ROI，加 4×4 窗口注意力（**免训练**） | 18.2/33.2 → **34.7/60.3** |
| **A1** | 把局部性修好之后的**全局图文检索 R@1** | **67.0 → 28.4**（region 检索 34.7 → 57.1） |
| 可训层数 3/6/9/12 | | 45.0 / 59.4 / 68.7 / 72.1 |
| 学生输入分辨率 320/640/1024 | | 46.5 / 67.1 / 72.1 |
| 网格块数 M=4/6/8/10 | | 71.3 / **72.1** / 71.6 / 70.0 |
| 8 | CC3M 1 epoch 也有效 | ——（正是我们的数据规模） |

三条要点：
1. **差距的成因是全局注意力**：只换成 4×4 窗口注意力、一步不训，稠密 ROI 就从 18.2 涨到 34.7
   → ViT 的 patch 特征本身已经被全局 attention 抹平了局部性。
2. **Table A1 是对我们最危险的一个数**：把局部性修好，全局图文检索从 67.0 掉到 28.4。
   我们的主目标是 CLIP 检索/分类，这条 trade-off 直接顶在主目标上。
3. **不是"最后一层的问题"**：可训层数 3→12 单调涨到 72.1，说明要改的是整条 trunk；
   而**分辨率是主要补偿手段**（320→1024 涨 25.6 点）。
4. **CNN 与 ViT 分界线**：RN50x64 在 640px 以上稠密 ROI **反超**真 crop
   → 「特征 ROI 能不能替代 crop」是**架构相关**的，CNN 的正面结论不能搬到 ViT。

⚠️ **我们自己有反向证据，要一起写清**：本项目的区域监督**已经**在最后一层特征图上做
roi_align 并且有效（VOC penult 24.23 → 47.23）。这与 CLIPSelf 的负数**不冲突**——
CLIPSelf 量的是**免训练**直接拿来用，我们是把它**当训练目标去对齐**。
这个区别正好界定了风险的大小：拿来当损失是安全的，拿来当**唯一的视图来源**没人验过。

## 唯一的正面先例：STiCA（arXiv 2103.10211，ICCV 2021）

全文献里唯一明确做「Feature Crop」并报了提速的工作。Tab 1(f) GPU-h/epoch：

| 形式 | GPU-h/epoch |
|---|---|
| 像素 6 个 small view | **100.7** |
| 像素 1 个 small view | 46.7 |
| **特征 crop** | **30.0** |

→ 相对 6 view 是 **3.36×**；相对 1 view 是 **1.56× 且精度 +1.1（60.4 vs 59.3）**；
且**特征 crop 的成本对 crop 数量几乎不敏感**（29.3 → 30.0，+2.4%）——这正是我们想要的性质。

**但三条硬性差异让它不能当依据**：
1. 骨干是 **R(2+1)D-18 三维 CNN**，不是 ViT（见上面 CNN/ViT 分界线）。
2. 特征图只有 **7×7**，而它取的 crop 是 **6×6 of 7×7 ≈ 全图的 86%**
   → 那是**语义上的多尺度全局视图**，**根本不是 DINO 的 local crop**。
3. 特征 crop 取自**两段独立增强的 clip**，即**从来不是同一次前向** → 仍然是跨视图。

它自己的 §7.5 明确担心**泄漏**（同一次前向里，"局部"特征已经看过全图），
辩解是「有效感受野 ≪ 理论感受野」——而这条辩解正是 CLIPSelf 在 ViT 上**推翻掉的**
（4×4 窗口注意力一改就涨 16 点 ⇒ ViT 的有效感受野确实是全局的）。

## 反面先例：EsViT（arXiv 2106.09785，ICLR 2022）

它**故意在复用的特征上"加"一个区域损失**，而不是用它**替换** crop。
Appendix C.2 Table 9(a)，**monolithic ViT-S，T=196（正是我们的 token 数）**，bs12：

| | 显存 | s/iter |
|---|---|---|
| `L_V` | 3533 MB | 0.238 |
| `L_V + L_R` | **14128 MB（4.00×）** | **0.352（1.48×）** |
| Swin-T 同比 | 1.59× | 1.15× |

原文明确写它「对 monolithic Transformer 会很快 OOM」。
⚠️ **这是对提速预期最大的威胁**：省掉 local crop 前向省的是**前向算力**，
而稠密区域损失自身在 monolithic ViT 上是 **O(T²)**，T=196 时**可能把省下来的全吃回去**。
→ 起实验前必须先在小规模上量这一项，不能只算「省了几个 token」。

两条附带结论（对损失形式的选择有直接价值）：
- **softmax 原型 ≫ MSE**：MSE 的 kNN 72.6 **比不加这个损失（74.2）还差**。
- **非对比的 argmax 形式** +0.7 linear / +1.8 kNN，而**对比式的 DenseCL −3.9 / −7.0**
  → 沿用现有 `DINOHead` 的 softmax 原型，别改成对比式。

## FineCLIP（NeurIPS 2024，无 arXiv 编号）

用户提到的两篇之一。**学生用特征 ROI，但老师仍然重新过真 crop** ——
即它也没敢让两侧同源。

- Table 1 #1：**只用 `L_SD`（自蒸馏）会塌到 0.0 / 0.0 / 0.0 / 0.1**。
  ⚠️ 限定：它的老师用真 crop，所以这条塌只证明「**全局目标是必须的**」，**不证明泄漏**。
- Table 4 计时：CLIP 6 min/epoch → CLIPSelf 10 min（**~1.67×**）→ FineCLIP 11 min / 36 G。
- **Fig 2 / Table 7，CC2.5M（正是我们的数据规模）**：CLIPSelf 把检索打烂 ——
  **Flickr I2T 81.6 → 33.8、COCO 51.1 → 18.8**；RegionCLIP → 3.9 / 2.0。
  → 与我们自己观察到的「局部涨、全局掉」trade-off 同型，而且在**小数据上更凶**。

## 加一路真像素视图的价格：SoCo（arXiv 2106.02637）

给出唯一一个干净的「多加一路真 crop 值多少」的数：**+0.6 AP^bb / +0.1 AP^mk**（Table 4）。
→ 反过来读：**这一路本来也不太值钱，替换它的收益上限不高，风险却全在下游。**

两条工程告警：
- **框尺寸不敏感**（96–192 → 42.0–42.3）→ ROI 大小不是关键旋钮。
- **EMA τ 极其致命**（0.98 → **35.0**，0.99 → 42.3）。
- **随机框在 K=4/K=8 直接 NaN**，而同 K 的 selective search 没事
  → **绝对不要用随机框**，用 CLIPSelf 式的 M≈6 网格块。

## 若要做，风险最小的形式（供 Task #37 预登记参考，不是结论）

**保留 2 个真全局 crop 照常前向，只把 8 个 local crop 换成从这两张全局特征图上取的 ROI。**

理由逐条对上上面的证据：
- **仍然跨视图**（ROI 取自 global crop A 的特征图、去配 global crop B 的输出）
  → 堵住泄漏，也与全部文献惯例一致。
- **全局对比目标在场** → 避开 FineCLIP Table 1 #1 那种塌。
- 省掉的是学生视觉塔 token 的 **~43%**：`2×197 + 8×37 = 690`，其中 local = `296/690`。
- 框用 **CLIPSelf 式 M≈6 网格块**，**不用随机框**（SoCo 的 NaN）。
- 头沿用现有 `DINOHead` softmax 原型（EsViT：MSE 比不加还差）。
- **先在小规模量 EsViT 那个 O(T²) 惩罚**，确认省下来的没被吃回去，再谈全程。

必须带的对照臂（否则判不了）：真 crop DINO（现有路径）、只换视图来源的单变量臂、
以及一个不带 DINO 的裸臂。
