# 区域-短语监督：CC3M 上在当前 baseline 之上唯一同时抬高图像塔与分类能力的路线

*创建: 2026-08-25 | 更新: 2026-08-27（新增 OVSS 局部口径 §5.8：区域监督 ×8，
但 `region_weight` 在这个口径上方向相反）
| 基座: PE-Core-B-16-dinov3 + VISReg-E + 256 ctx | 12 组 10-epoch 训练*

本页是区域-短语对比监督（FG-CLIP 2 风格 `region_loss`）这条线的实现与结果主页。
评测方法论（口径绑定 / 零重叠 / 全量报数）见 [[eval_protocol]]，**不在本页重复**。
长文本路线见 [[longclip_01_pcm]]；IN-1k 全量口径重测的跨路线总表见 [[in1k_fullscope_retest]]。

## 0. 结论速览

1. **在当前 baseline（VISReg-E）之上，区域监督是目前唯一让图像塔真正变好的做法。**
   ⚠️ **"唯一"必须带这个限定** —— 历史上有非区域路线抬高过图像塔且幅度更大：
   正则形式 `SIGReg → VISReg` 拿到 IN-1k top1 **+2.03**（见 [[visreg_vs_sigreg]]），
   正则作用位置从 clip embedding 挪到 cls raw token 又值 +1.0 COCO。
   这两条不构成反例（`gt_base` 已经站在 VISReg-E 上，收益已被吸收进 baseline），
   但去掉限定语就会被这段历史打脸。
   8 个 `region_weight=0.2` 变体的 IN-1k k-NN backbone（全量 50000 图）全部落在 46.26~47.14，
   `gt_base` 是 44.73，**Δ = +1.53 ~ +2.41，即 5~8 倍 2σ（0.30）**。
   把权重开到 0.5 是 **49.49（Δ = +4.76，16σ）**，开到 1.0 是
   **51.02（Δ = +6.29，21σ，全项目首次过 50）**，开到 2.0 是
   **52.74（Δ = +8.01，27σ，当前最优）**（§5.7）。
   对照的长文本路线全系为负（`pcm_w0.2` −3.29，`gemma_dense` −11.77）。
2. **W=0.2 时四个口径里三个同时显著为正**：k-NN +1.5~2.4、IN-1k zero-shot +3.9~4.4、
   COCO i2t +2.3~4.3、COCO t2i +1.8~2.8。Urban-1k 长文本基本不动（多数落在噪声内），
   符合预期 —— 区域短语是**短**文本，这条线不碰长文本能力。
   ⚠️ **W=0.5 时 Urban 也起来了**（i2t +5.40 / t2i +3.30 vs `gt_base`，均过 2σ=1.92），
   所以"这条线完全不碰长文本"只在小权重下成立；加大权重后**七个口径一起动**（§5.7）。
   ⚠️⚠️ **Urban 到 0.5 就饱和，到 2.0 开始下跌**：0.5 → 1.0 期间其余五个口径继续涨 +1.5~2.4，
   Urban i2t **−0.10 / t2i +1.40 全落在噪声内**；1.0 → 2.0 则出现**全扫描第一个显著负项**
   Urban t2i **−2.50（1.3× 2σ）**，i2t −0.50 仍在噪声内。所以准确说法是
   「区域监督对长文本有一段**有限的**正向作用，在 W≈0.5 处用完，W≥2.0 后开始拿长文本换图像塔」（§5.7）。
3. **增益不是来自 resize 增广。** 区域训练必须用 resize（保持框坐标对应），
   为此单独跑了 A′ = `gt_base` + resize。A′ 在**六个口径里五个显著为负**
   （k-NN −1.72 / IN-1k −0.75 / COCO i2t −1.68 / t2i −1.33 / Urban t2i −2.70）。
   所以区域组的 +2 点是区域监督本身给的，而且是在**先扣掉 resize 的 −1.7 点之后**净赚的。
4. **在 `region_weight=0.2` 这一个工作点上，8 个消融变体之间几乎不可分辨。**
   IN-1k 全距只有 0.53（1.7× 2σ），k-NN 0.88（2.9×）。8 组内部
   `r(k-NN, IN-1k) = +0.100` —— 组间差异已进入噪声与随机涨落的混合区。
   已试过的五个旋钮（gather / shared-scale / K / crop-aug / verdict）在这个工作点上全部调平。
   ⚠️ 但这个"调平"是**在权重被压到 0.2、区域分支贡献很小的前提下**测出来的，
   现在工作点要挪到 0.5（§5.7），这五条结论都需要在新工作点复核 —— **别当成永久结论**。
5. **`region_weight` 是这条线上最重要的旋钮；在**全局**口径上方向与长文本路线相反。**（§5.7）
   ⚠️ **"越大越好"只在全局口径上成立** —— 2026-08-27 新增的 OVSS 局部口径
   给出完全相反的方向，见下面第 8 条与 §5.8。
   9 组全部照搬 FG-CLIP 2 的 0.2，一次没扫过。**0.2 → 0.5 → 1.0 → 2.0 三跳，
   五个非长文本口径单调上升且每跳都过 2σ**：k-NN bb 46.81 → 49.49 → 51.02 → **52.74**、
   IN-1k 27.50 → 30.45 → 32.07 → **34.00**、COCO i2t 26.30 → 29.98 → 32.42 → **34.04**。
   相对 `gt_base`，W=2.0 是 **+2.20 ~ +10.90 七口径全线正**。
   对比 `pcm_weight` 是越小越好（1.0 → 0.2 值 +6.5 点 COCO i2t），
   `region_weight` 是**越大越好，到 2.0 仍未见顶**（此时区域损失已占总损失 68%，
   "辅助损失不该压过主损失"这条直觉在这里已被推翻两次）。
   ⚠️ **"增量在减速"这个说法已被推翻** —— 按等倍跨度（每次 ×2）比，图像塔口径的增量
   反而在**加速**：k-NN bb +1.53 → **+1.72**、proj +1.59 → **+1.83**、IN-1k +1.62 → **+1.93**；
   只有 COCO 检索在减速（i2t +2.44 → +1.62、t2i +1.87 → +1.12）。
   旧结论错在拿 ×2.5（0.2→0.5）和 ×2（0.5→1.0）两个不等跨度作比。
   **旧的"推荐配方 = C1"与"W=1.0 最优"均作废**，*全局口径上*当前最优已知 =
   **C1 的一切 + `region_weight=2.0`**。W=4.0 在跑（§6.2）。
   **但选型不能只看全局口径**：同一批 ckpt 在 OVSS 上是 W 越大越差
   （penult 38.42 → 24.23），所以"最优 W"现在必须写成"给定口径下的最优 W"（§5.8）。
6. **`gemma verdict` 过滤这个子方向可以关掉。** 强度从 firstbox → hard，
   IN-1k +0.51 ✅、COCO i2t **−1.40** ✅、Urban i2t **−3.30** ✅ ——
   是真 trade-off 而非净损失，但收益量级远小于代价，不值得继续。
7. **叠加到长文本路线（G 组）成立。**（§5.6）
   G = PCM + 区域，七个口径**全部不低于 `gt_base`**（唯一非正项 k-NN bb −0.20 落在噪声内），
   区域监督填掉了 PCM 图像塔坑的 **94%**，而 Urban i2t 拿到 **+49.30** ——
   比它的长文本父本 `pcm_w0.2` 还高 8.10 点，超出"≈父本水平"的预期。
   ⚠️ G 用的是 `region_weight=0.2`。W=0.5 单跑在**五个口径上反超 G**
   （k-NN bb +4.96 / proj +3.88 / IN-1k +4.89 / COCO i2t +1.16 / t2i +3.00），
   W=1.0 拉到 +6.49 / +5.47 / +6.51 / +3.60 / +4.87，**W=2.0 拉到
   +8.21 / +7.30 / +8.44 / +5.22 / +5.99**，
   G 只在 Urban 上遥遥领先（vs W=2.0 为 i2t +44.50）。
   **选型（暂定）**：要长文本能力 → G，但 G 自己必须按最优 W 重跑；
   只要图像塔 + 分类 + 短句检索 → **W=2.0 单跑**。
   ⚠️⚠️ 「G 必须按最优 W 重跑」这条的前提已被第 8 条推翻 —— G 的低 W 在局部口径上是优点。
8. **⚠️⚠️ 新增局部口径（OVSS mIoU）把上面第 5、7 条掀翻了一半。**（§5.8，2026-08-27）
   新入口 `scripts/eval/eval_ovss.py`，PASCAL VOC 2012 val 全量 1449 张，SCLIP 同协议，
   无任何推理期改造。这是本项目**第一个局部表征硬指标** —— 此前七个口径全是全局的。
   两个结论：
   (a) **区域监督在这里是量级差异**：`gt_base` 5.17 → 区域组 38~50，约 **×8**。
   `gt_base` 的 aAcc 只有 10.2%，即**当前 baseline 的 patch 表征基本不可分割**，
   与 §5.1 机制假说（VISReg 把 patch 间余弦推高 0.137→0.161）一致。
   A′ `gt_resize` 是全表最低（4.98 / 3.42），resize 混淆项在局部口径上被排除得更彻底。
   (b) **`region_weight` 在这个口径上越小越好，与五个全局口径完全相反**：
   penult 38.42 → 37.32 → 31.95 → 24.23（**单调，−14.19**），last 0.5 见顶后跌 −8.40。
   而同一批 ckpt 在 k-NN / IN-1k / COCO 上是每跳过 2σ 单调上升。
   → W=2.0 时 Urban t2i 那个 −2.50 不再是孤立负项：**把区域分支压得越重，
   全局判别性越强，而局部可分割性与长文本能力一起被牺牲。**
   G 组（PCM+区域，W=0.2）在两种读出上都是全表最高（39.10 / 49.96）。
   定位：我们最好的 49.96 ≈ 原版 CLIP ViT-B/16 在 WIT-400M 上的 49.4（SCLIP 论文同协议），
   而我们用 CC3M 2.9M 且无改造 —— 但骨干与类名列表都没对齐，**不是同条件比较**（§5.8）。

## 1. 问题

`gt_base` 用整图 + 一句短 caption 做 SigLIP 对比。
一张图里的多个物体、它们的属性和空间关系，全部被压进一个全局 token 的一次对齐里。
[[longclip_01_pcm]] 的结论是：往**文本侧**加信息（更长的 caption）能大幅提升长文本检索，
但**图像塔会退化 3~12 点**（§5.3），因为长 caption 把视觉表征往"描述性语言"的方向拉。

区域监督换一个方向：不改文本长度，而是**增加对齐的粒度** ——
把「整图 ↔ 一句话」拆成「整图 ↔ 一句话」+「K 个区域 ↔ K 个短语」。
每个区域短语仍然很短（几个 token），所以不引入长文本的副作用。

假设：细粒度对齐会强迫图像塔把**局部可判别信息**保留在 patch 表征里，
而不是让全局 pooling 把它抹掉 —— 如果成立，k-NN backbone 应该上升。
这是 [[longclip_01_pcm]] §6.1「图像塔优化不在本轮范围内」这个判断的直接反例检验。

**定长 K + mask 是关键工程约束**：`region_texts` 是 `[B,K,L]`、`region_boxes` 是 `[B,K,4]`，
无效位补 0 并由 `region_mask` 屏蔽。这样每张卡的张量尺寸恒定 ——
这是 `region_gather='gather'` 能做 `all_gather` 的前提（C2 组）。

**必须用 resize 而非 crop 增广**：随机裁剪会让归一化框坐标失效。
为了把「resize 本身的影响」与「区域监督的影响」分开，单独训了 A′ 对照（见 §3）。

## 5. 结论

### 5.1 区域监督真的改善了图像塔 —— 这是本项目第一次

`gt_base` 系四次同配方运行的 k-NN backbone 是 44.47 / 44.73 / 44.82 / 44.64
（mean 44.665，2σ = 0.30）。**8 个区域变体的最小值 46.26 比这四次的最大值 44.82 还高 1.44 点。**
不存在重叠，不需要讨论显著性。把 `region_weight` 从 0.2 开到 0.5 是 **49.49**，
开到 1.0 是 **51.02 —— 比 `gt_base` 最大值高 6.20 点（21σ），首次突破 50**，
也比 8 个 W=0.2 变体的最大值 47.14 高 3.88 点（§5.7）。

这个结果直接限定了 [[longclip_01_pcm]] §6.1 的一条旧判断。原话是
「图像塔是否被文本侧优化改善：k-NN 给出否定答案 …… **图像塔优化不在本轮范围内**」。
现在必须加限定词：**那个否定答案只对「往文本侧加长文本」这一类做法成立。**
换成「增加对齐粒度」，图像塔立刻涨 2 点（把权重开到 1.0 是 6.3 点）。两条线的对照：

| 路线 | 做法 | k-NN bb Δ vs gt_base | IN-1k Δ | COCO i2t Δ | Urban i2t Δ |
|---|---|---|---|---|---|
| 长文本（PCM 最优 w0.2） | 文本变长（132 tok），双分支 | **−3.29** ✅ | −1.74 ✅ | +5.46 ✅ | **+41.20** ✅ |
| 长文本（纯 dense） | 文本变长，单分支 | **−11.77** ✅ | −22.31 ✅ | −15.44 ✅ | +33.30 ✅ |
| **区域监督（C1, W=0.2）** | 对齐变细（12 个短语） | **+2.08** ✅ | **+4.23** ✅ | **+3.16** ✅ | +1.80 ❌ |
| **区域监督（W=0.5）** | 同上，权重 ×2.5 | **+4.76** ✅ | **+7.18** ✅ | **+6.84** ✅ | **+5.40** ✅ |
| **区域监督（W=1.0）** | 同上，权重 ×5 | **+6.29** ✅ | **+8.80** ✅ | **+9.28** ✅ | **+5.30** ✅ |
| **区域监督（W=2.0）** | 同上，权重 ×10 | **+8.01** ✅ | **+10.73** ✅ | **+10.90** ✅ | **+4.80** ✅ |
| **G = PCM + 区域（W=0.2）** | 两者同时上 | −0.20 ❌ | **+2.29** ✅ | **+5.68** ✅ | **+49.30** ✅ |

两条线的**收益结构完全互补**：长文本只买到长文本能力（+41），并且付出图像塔和分类能力；
区域监督买到图像塔 + 分类 + 短句检索，长文本只在 W≤0.5 这一段跟着涨一点然后饱和。
这是 G 组（PCM + 区域叠加，`pcmregw0.2p0.2`）值得跑的全部理由 ——
两者的代价与收益不在同一个维度上，有可能不冲突。
**✅ 已验证成立，见 §5.6**：G 的图像塔回到 `gt_base` 水平（−0.20，噪声内），
分类 +2.29，而 Urban 拿到 +49.30 —— 比它的长文本父本还高 8.10 点。

#### 一个机制假说：区域监督补的正是 VISReg 覆盖不到的那根轴（2026-08-26 新增）

本页此前一直只说"图像塔变好了"，没有机制解释。VISReg 线的残差诊断
（`scripts/tools/diag_residual_dominance.py`，见 [[visreg_vs_sigreg]]）给了一条线索：
**当前 baseline 自带的 VISReg 会升高 patch 之间的余弦相似度** ——
`X_sum.patch_cos` 0.137 → 0.161、`X_attn` 0.796 → 0.848。
原因是 VISReg 只约束 **CLS 的跨通道各向同性**，管不到**跨空间位置的可区分性**。

区域-短语对比恰好把损失直接压在 `roi_align` 出来的**局部** patch 池化特征上，
逼不同位置的 patch 分开 —— **这正是 VISReg 结构上覆盖不到的那根轴**。
如果这个假说成立，它同时解释三件事：为什么这条线是当前 baseline 之上唯一抬图像塔的；
为什么 `region_weight` 可以一直开大而不塌（它不与主对比项争同一根轴）；
以及为什么 K=12 明显好于 K=4（覆盖更多空间位置）。

⚠️ **这是假说，未验证。** 直接的验证是：拿区域组和 `gt_base` 各跑一次
`diag_residual_dominance.py`，看 `patch_cos` 是否随 `region_weight` 单调下降。
成本很低（纯推理），已登记 §6.3。真正的硬指标是开放词表分割 mIoU，见 §6.3 的评测空洞条。

**一条独立证据（不来自本页，来自 VISReg 线的 21 个 run）：作用位置比作用强度重要得多。**
把 VISReg 从 CLIP embedding（`clip`，1024d）挪到 backbone raw token（`cls`，768d），
COCO **+1.0pt**；而强度跨 4 个数量级（0.5×~1e4×）扫下来下游只动 **±0.5pt**
（21 个 run 的汇总表见 [[visreg_all_attempts]]，详细过程见 [[visreg_vs_sigreg]]）。
那条线自己给的解释是"`cls` 更靠前、离对比损失更远，冲突小；`clip` embedding
正是对比损失直接在用的东西"。

这对本页有两点意义：
1. **区域监督也作用在 backbone 侧** —— `roi_align` 取的是倒数第二层 patch map，
   同样远离 clip embedding。"远离对比损失的辅助信号能加得进去、还能加得很重"
   在两条独立的线上都成立，这是机制假说的旁证。
2. 它顺带解释了那条线的 `xm_pair` / `xm_dist` 为什么全线失败 ——
   跨模态"相对目标"被"两塔必须同维"逼进了 clip 空间，正好落在冲突最大的位置。

### 5.2 增益不来自 resize 增广（A′ 消融）

区域监督有一个绕不开的耦合项：**框坐标已归一化，随机裁剪会让它失效，所以必须换成 resize**。
如果 resize 本身有好处，那区域组的提升就说不清了。

A′ = `gt_base` 配方 + 只换 resize 增广，其他全同。结果是**六个口径里五个显著为负**：
k-NN −1.72（5.7σ）/ k-NN proj −2.01 / IN-1k −0.75（2.3σ）/
COCO i2t −1.68（2.2σ）/ COCO t2i −1.33（10σ）/ Urban t2i −2.70。

所以 resize 是**净损失**，区域组的账应该这样记：

```
C1 相对 gt_base 的 k-NN 增益  = +2.08
其中 resize 增广贡献            = −1.72   （A′ 实测）
区域监督本身的贡献             = +3.80   （C1 − A′）

W=0.5 相对 gt_base 的 k-NN 增益 = +4.76
区域监督本身的贡献             = +6.48   （W0.5 − A′）

W=1.0 相对 gt_base 的 k-NN 增益 = +6.29
区域监督本身的贡献             = +8.01   （W1.0 − A′）
```

**区域监督本身值 +3.8 点 k-NN、+4.98 点 IN-1k、+4.84 点 COCO i2t** —— 比总表上看到的更大，
因为它先要补掉 resize 挖的坑。开到 W=0.5 是 **+6.48 k-NN / +7.93 IN-1k / +8.52 COCO i2t**，
开到 W=1.0 是 **+8.01 / +9.55 / +10.96**（均相对 A′）。
这也说明：**如果能不丢区域样本地把裁剪增广加回来，这条线还有 1.7 点的空间。**
H 组（`--region-crop-aug`）就是这个尝试，坐标重算是对的、裁剪强度也与 `gt_base` 相同，
但为保证短语-区域对应而丢掉 20~40% 的框，净收益为负（§5.4）。
**这 1.7 点仍然挂着，缺的不是"框跟着裁剪走"，而是"框跟着裁剪走且不用丢"。**

### 5.3 8 个变体之间已经调平了 —— 但只在 W=0.2 这一个工作点上

| 口径 | 8 组全距 | 2σ | 全距 / 2σ |
|---|---|---|---|
| IN-1k zs | 0.53 | 0.32 | **1.7×** |
| k-NN proj | 0.67 | 0.29 | 2.3× |
| COCO i2t | 1.98 | 0.75 | 2.6× |
| Urban i2t | 5.10 | 1.92 | 2.7× |
| k-NN bb | 0.88 | 0.30 | 2.9× |
| COCO t2i | 0.91 | 0.13 | 7.0× |

除 COCO t2i 外，所有口径的**全部 8 组挤在 2~3 倍噪声地板之内**。
8 组内部算相关性：`r(k-NN bb, IN-1k) = +0.100` —— 几乎正交。
把 A′ 加进来（9 组）后 `r = +0.972`，靠的完全是 A′ 这一个远点。

**结论：这 8 个变体之间的差异主要是 run-to-run 涨落，不是配置带来的系统差异。**

⚠️ **但不要把这一条读成"这条线的旋钮都调平了"。** 2026-08-25 的版本正是这么写的
（原话「这条线的旋钮已经调平，继续做同类消融不会有收益。下一步应该换维度，
而不是继续扫参」），**当天晚上扫 `region_weight` 就拿到七口径 +2.2~+3.7**（§5.7）。
两件事的区别：那 8 个变体动的是区域分支的**内部结构**（负样本池、scale 共享、
区域数、增广、数据过滤），`region_weight` 动的是区域分支**在总损失里占多大比重**。
前者调平不蕴含后者调平。教训：**判断"旋钮调平"之前，先确认该旋钮真的被扫过。**

### 5.4 四个消融方向的逐条判定（相对 C1）

| 消融 | k-NN bb | IN-1k | COCO i2t | COCO t2i | Urban i2t | 判定 |
|---|---|---|---|---|---|---|
| C2 `gather` | −0.18 ❌ | −0.06 ❌ | −0.48 ❌ | **−0.30** ✅ | −1.80 ❌ | **无收益**，t2i 上还显著为负 |
| C3 `shared-scale` | +0.20 ❌ | −0.21 ❌ | +0.14 ❌ | −0.01 ❌ | **+2.80** ✅ | **等价**，只 Urban 一项显著 |
| C4 `K=4` | −0.25 ❌ | **−0.37** ✅ | **−0.88** ✅ | **−0.75** ✅ | +0.60 ❌ | **K=12 优于 K=4** |
| H `crop-aug` | **−0.55** ✅ | −0.12 ❌ | −0.40 ❌ | **−0.40** ✅ | −1.40 ❌ | **有害**，图像塔上显著为负 |

**C2 / `region_gather=gather` 无用。** 把区域负样本池从单卡扩到全局 8 卡
（有效池 ×8）在五个口径上一个都没涨，COCO t2i 还掉 0.30（2.3σ）。
区域短语的负样本本来就足够多（`B×K = 512×12 = 6144` 每卡），扩池没有边际收益，
只增加通信。**取 `local`。**

**C3 / 共享 `logit_scale` 与独立等价。** 四个短文本口径全部落在噪声内。
Urban i2t +2.80 是唯一显著项，但 Urban 的 2σ 最大（1.92）且这条线不训长文本，
单点显著不足以支撑结论。**可以共享（省一个参数），也可以不共享，无所谓。**

⚠️ **这一条推翻了旧结论。** 子集口径下 C3 的 IN-1k 是 30.00%，是全部区域组里最高的，
据此写过「C3 shared-scale 有优势」。全量重测后 C3 是 27.29，
在 8 组里**排第 6**（[[in1k_fullscope_retest]]）。那个优势是子集采样偏置造出来的。

**C4 / `K=4` 明确差于 `K=12`。** IN-1k −0.37、COCO i2t −0.88、t2i −0.75，三项显著为负。
区域数量确实有用，12 个比 4 个好。（K>12 未试 —— 这是 §6 里唯一还有意义的扫参方向。）

**H / `crop-aug` 有害。** 动机是把 §5.2 算出的 resize −1.7 点坑填回来。
结果 k-NN −0.55（1.8σ，显著为负）、COCO t2i −0.40（3.1σ）。**没填坑，反而更差。**

⚠️ **实现细节已核对（2026-08-26），此前对失败原因的猜测是错的。** 代码不是
「约束裁剪窗口去保框」，而正是「自由裁剪 → 按裁剪窗口重算框坐标 → 丢弃裁出画面的框」
（`data.py:29 RandomResizedCropWithBoxes`，`main.py:258` 接线；
H 的启动日志实录 `scale=(0.9, 1.0)`，与 `gt_base` 默认裁剪强度**完全相同**）。
所以旧说法「保框约束让裁剪只能很轻微，增广强度不够」不成立 —— 增广强度是一样的。
真正的代价只剩一个：**完全包含策略下丢框率 20~40%，有效区域样本被砍掉近三分之一**，
这份损失大于裁剪带回来的正则化收益。**方向关掉，但记账要记对。**

⚠️ **本节全部判定都是在 `region_weight=0.2` 下测的。** 那个工作点上区域分支只占总损失
很小一份，四个消融改的都是区域分支的内部结构 —— 分支本身权重小，其内部改动的信号
自然更小，**"落在噪声内"有一部分可能是这么来的，而不是真的等价**。
W=0.5 / W=1.0 把区域分支的比重提了 2.5 / 5 倍（§5.7，区域损失占比 18% → 35% → 51%），
K / gather / scale 共享这些旋钮
在新工作点上有没有可分辨的差异，**本轮没测**。K=12 vs K=4 是唯一在 W=0.2 下就已经
显著（三口径）的一条，它的方向大概率能外推；其余三条应当视为**未在新工作点复核**。

### 5.5 `gemma verdict` 过滤：真 trade-off，但不划算

E1/E2/E3 是同一条子线的三档强度：用 gemma 对每个「框 + 短语」判定是否真实对应，
然后 `firstbox`（最弱，只保留第一个框）→ `soft`（按判定分软筛）→ `hard`（只留判定为真）。

| 对比 | k-NN bb | IN-1k | COCO i2t | COCO t2i | Urban i2t |
|---|---|---|---|---|---|
| E2 soft − E1 firstbox | −0.23 ❌ | +0.03 ❌ | −0.34 ❌ | +0.02 ❌ | −1.70 ❌ |
| **E3 hard − E1 firstbox** | +0.03 ❌ | **+0.51** ✅ | **−1.40** ✅ | **−0.54** ✅ | **−3.30** ✅ |
| E1 firstbox − C1（无 verdict） | +0.30 ≈2σ | **−0.35** ✅ | **+1.10** ✅ | +0.14 ✅ | +1.00 ❌ |

**E1 → E2 完全不可分辨**（五个口径全落噪声内）。soft 这一档没有存在意义。

**E1 → E3 是真 trade-off**：分类侧 +0.51（1.6σ，显著），
检索侧 COCO i2t −1.40（1.9σ）、t2i −0.54（4.2σ）、Urban i2t −3.30（1.7σ）。
方向相反且都显著 —— 加大 verdict 过滤强度把模型从"检索友好"推向"分类友好"。

⚠️ **修正 2026-08-24 的会话结论。** 当时（子集口径）报的是
「verdict 强度 ↑ → IN-1k 单调上升 25.50 → 27.45 → 28.20，各差远超 2σ」，
并据此写过「没有分类侧补偿，verdict 是净损失」。两处都要改：
- 全量口径下三档是 27.15 / 27.18 / 27.66，**E1→E2 是 +0.03（噪声内），不是 +1.95**。
  单调上升这个描述不成立，只有 E3 一档真的高。
- 分类侧**确实有补偿**（+0.51 > 2σ=0.32）。所以不是"净损失"，是 trade-off。

但结论上仍然不建议继续：**+0.51 的分类收益换 −1.40 / −3.30 的检索代价，
量级差 3~6 倍**，而且需要额外一遍 gemma 标注。
E1（最弱档）相对 C1 在 COCO i2t 上 +1.10 显著为正，是全表 COCO 最高的一组 ——
如果只关心短句检索，E1 有价值；否则 **C1 已经够了，verdict 这个子方向可以关掉**。

### 5.6 G 组：PCM + 区域叠加 —— 互补性假设成立，且超出预期

`visreg_gemma_pcmregw0.2p0.2_projective_E_0825_1238`，epoch_10，三条监督分支：
主分支 `SigLIP(img, caption_dense)`（长文本）+ PCM 短分支 `SigLIP(PCA_32(img), caption_short)`
+ 区域分支 `SigLIP(RoIAlign(patch), 短语)`。`region_weight=0.2` `pcm_weight=0.2` 共享 scale。

| 口径 | **G** | gt_base | pcm_w0.2 | C1 |
|---|---|---|---|---|

**四条结论：**

1. **G 是本项目第一个七口径全面不低于 `gt_base` 的配方。** 唯一的非正项是 k-NN backbone
   −0.20，落在 2σ=0.30 之内（不可分辨）；其余六项全部显著为正。
   此前没有任何单一路线做到过这件事 —— 长文本买 Urban 要赔图像塔和分类，
   区域买图像塔和分类则完全不动 Urban。

2. **区域监督把 PCM 挖的图像塔坑填掉了 94%。** `pcm_w0.2` 相对 `gt_base` 是 −3.29（11σ），
   叠加区域后残余只有 −0.20（噪声内）。这正是 §5.1 预测的机制：
   两条线的代价与收益在不同维度上，所以能互相抵消而非互相打架。

3. **Urban 反而超过了它的长文本父本 +8.10（i2t）/ +4.80（t2i）—— 这不在预期内。**
   §6.2 原本的期望是"Urban ≈ PCM 水平（+40）"，实测是 +49.3。
   即**加区域监督不但没损害长文本检索，还把它推高了**。
   一个可能的解释：区域-短语对齐让 patch 级表征更可判别，长描述里的多物体
   细节因此更容易被匹配上 —— 但这只是猜测，本轮没有能验证它的实验。

4. **相对 C1 是一笔清晰的 trade-off**：图像塔 −2.28 / 分类 −1.94 / COCO t2i −0.76，
   换 Urban +47.5 与 COCO i2t +2.52。**若目标含长文本能力，G 是当前最优配方；
   若只要图像塔和分类，C1 仍然更好。**

**⚠️ 可比性限制（重要）**：G 用 `clip_train_pcmregion.tsv`，样本 **198.4 万**，
受 dense caption 覆盖率所限。

已扫四点（0.2 / 0.5 / 1.0 / 2.0），**在五个非长文本口径上单调上升、每跳都过 2σ**。

**五条结论（覆盖三点扫描）：**

1. **旋钮方向与长文本路线正好相反。** `pcm_weight` 是越小越好（最优区间 [0.1,0.2]，
   见 [[longclip_01_pcm]]），`region_weight` 是**越大越好，到 1.0 仍未见顶**
   （五个非长文本口径 0.2→0.5→1.0 单调上升，每跳都过 2σ）。
   两者不能互相类推 —— 排这个实验时用的类比只在"权重敏感"这一点上成立，
   在"往哪个方向调"上完全反了。

2. **旧的"推荐配方 = C1"作废，当前最优已知 = C1 的一切 + `region_weight=1.0`。**
   C1 在全部七个口径上被 W=0.5 压制，W=1.0 又在五个口径上压制 W=0.5，
   而这些都不需要任何额外数据或代码（只是一个浮点系数）。
   W=1.0 相对 8 个 W=0.2 变体各口径的最好成绩：
   k-NN bb 51.02 vs 47.14（+3.88）、IN-1k 32.07 vs 27.66（+4.41）、
   COCO i2t 32.42 vs 27.40（+5.02）、Urban i2t 23.60 vs 22.90（+0.70，噪声内）。
   **§5.4 那四个消融方向争的 0.2~0.9 点，全部小于这一个旋钮给的 4~5 点。**

3. **Urban-1k 也涨了，但只涨到 W≈0.5 为止。**
   W=0.2 下 Urban 基本不动（§4.1，5/8 组落在噪声内），本页原先据此写"符合预期，
   区域短语是短文本"。W=0.5 下 Urban i2t +5.40 / t2i +3.30（相对 `gt_base`）都过 2σ，
   推翻了"完全不碰"。但 **W=1.0 相对 W=0.5 是 i2t −0.10 / t2i +1.40，两项都在噪声内**,
   同期另五个口径还在涨 +1.5~2.4。
   所以最终说法是：**区域监督对长文本检索有一段有限的正向作用，在 W≈0.5 处用完；
   再加权重买到的全是非长文本口径。** 机制未验证 —— 与 §5.6 结论 3（G 组 Urban
   反超长文本父本 +8.10）指向同一个未解释现象，两处都提示"更可判别的 patch 表征
   帮助了长描述里的多物体匹配"，但仍是猜测。而"饱和"本身也提示这个帮助有上限：
   长上下文建模能力不是区域短语能替代的。

4. **扣掉 resize 之后的实值接近翻倍再翻。** 相对 A′（`gt_base` + resize，43.01/22.52/21.46）：
   W=0.5 是 k-NN **+6.48** / IN-1k **+7.93** / COCO i2t **+8.52**；
   W=1.0 是 k-NN **+8.01** / IN-1k **+9.55** / COCO i2t **+10.96**。
   C1 的对应值是 +3.80 / +4.98 / +4.84（§5.2）。

5. **W=0.5 / W=1.0 单跑都在五个口径上反超 G 组**（G = PCM + 区域，W=0.2）：

   | vs G | k-NN bb | k-NN proj | IN-1k | COCO i2t | COCO t2i | Urban i2t | Urban t2i |
   |---|---|---|---|---|---|---|---|
   | W=0.5 − G | +4.96 | +3.88 | +4.89 | +1.16 | +3.00 | −43.90 | −42.20 |
   | W=1.0 − G | **+6.49** | **+5.47** | **+6.51** | **+3.60** | **+4.87** | −44.00 | −40.80 |

   ⚠️ 但 G 用的 TSV 只有 198.4 万样本（W 扫描各组是 286.9 万，多 45%），这个对比不干净。
   直接推论：**G 组应当按 `region_weight` 的最优点重跑**（§6.3）—— G 里的区域分支
   现在确定是被压得太小了，差距还在随 W 变大而拉开。

**Δ(proj − bb) = −0.77（W=0.5）/ −0.71（W=1.0）/ −0.60（W=2.0）。** 8 个 W=0.2 区域组全部落在

### 5.8 OVSS mIoU：本项目第一个**局部**表征口径，它把 `region_weight` 的结论掀翻了一半

新入口 `scripts/eval/eval_ovss.py`（2026-08-27 建），PASCAL VOC 2012 val 全量 1449 张，
开放词表语义分割 mIoU。**协议与 SCLIP / ClearCLIP 系列严格一致**：短边缩放 336、
滑窗 224×224 / stride 112、20 个类名 × 80 个官方模板平均、无任何推理期改造、无后处理。
两种 dense 读出各报一遍：

- `penult`（倒数第二层 patch map → `visual.head`）—— **与训练时区域分支同一条路径**
  （`model.py:_roi_features` 只是把逐 patch 换成了 RoIAlign）。
- `last`（最后一层 patch token → `visual.head`）—— 对照项。

#### 结果（全量 1449 图，`neg_mode=projective`，`epoch_10`）

| 组 | `region_weight` | penult | last |
|---|---|---|---|
| `gt_base` seed 0 | — | 5.17 | 4.18 |
| `gt_base` seed 1 | — | 5.29 | 4.02 |
| A′ `gt_resize`（只换 resize 增广） | — | **4.98** | **3.42** |
| C1 `regw0.2` | 0.2 | 38.42 | 39.59 |

（最小的一个差值是 0.2→0.5 的 penult −1.10，仍是它的 7~9 倍）。

#### 四个结论

1. **区域监督在这个口径上是量级差异，不是几个点：5.2 → 38~50，约 ×8。**
   这是本项目第一次**直接测量**"图像塔学到了空间可区分性"，此前全靠 k-NN /
   分类 / 检索这些全局口径间接推断（§5.1）。
   `gt_base` 的 5.17 / 4.18 已经接近"随机猜"的水平（aAcc 只有 10.2% / 9.2%），
   也就是说**当前 baseline 的 patch 表征基本不具备可分割性** ——
   这与 §5.1 机制假说里"VISReg 会把 patch 间余弦推高（0.137→0.161）"完全一致。
2. **A′ 再次把 resize 增广排除干净**：4.98 / 3.42，是全表**最低**的两个数字，
   比 `gt_base` 还低。§5.2 在全局口径上的结论在局部口径上同向且更强。
3. **⚠️⚠️ 这个口径说 `region_weight` 应该开小，与五个全局口径完全相反。**
   penult 上从 0.2 到 2.0 **单调下降** 38.42 → 37.32 → 31.95 → 24.23（**−14.19**）；
   last 上在 0.5 见顶后下降 39.59 → 49.26 → 45.93 → 40.86（峰后 **−8.40**）。
   而同一批 ckpt 在 k-NN / IN-1k / COCO 上是 0.2→2.0 **单调上升每跳过 2σ**（§5.7）。
   → **§5.7 的"越大越好"必须改成"在全局口径上越大越好"。**
   这也让 W=2.0 时 Urban t2i 那个 −2.50 从"孤立的第一个负项"变成了
   **一个更大图景的一部分**：把区域分支压得越重，全局判别性越强，
   而**局部可分割性和长文本能力一起被牺牲**。
4. **G 组（PCM + 区域，W=0.2）在两种读出上都是全表最高**（39.10 / 49.96）。
   而 G 在全局口径上被 W≥0.5 的单跑组全面反超（§5.7 结论 5，差 +5.2~+8.4）。
   → **§6.3 里"G 按最优 W 重跑"这一项的前提没了**：G 的低 W 在这个口径上是优点，
   不是缺点。重跑仍值得做，但目的从"补上被压小的区域分支"改成"看 trade-off 曲线"。

#### 与业界数字的位置（仅供定位，不是同条件对比）

SCLIP 论文（arXiv 2312.01597v3）Table 1 的 VOC20 一列，同一套协议下：
原版 CLIP **49.4** / MaskCLIP 74.9 / GroupViT 79.7 / TCL 77.5 / SCLIP 80.4。
我们最好的 **49.96（G，last 读出）** 与"原版 CLIP ViT-B/16 在 WIT-400M 上训练"
的 49.4 基本持平，而我们用的是 **CC3M 2.9M**、且**没有任何推理期改造**。

⚠️ 这个对照有三处不可忽略的差异，**不要当成同条件比较**：
(a) 骨干是 `PE-Core-B-16-dinov3` 而非 OpenAI CLIP ViT-B/16，且带 VISReg；
(b) 类名列表用的是 20 个朴素名字，SCLIP 系列的 `cls_voc20.txt` 含同义词扩展，
    通常会高一点，我们这边没对齐；
(c) 我们的 `gt_base`（5.17）远低于它的 49.4 —— 同样是"无改造的 CLIP"，
    差距主要来自数据规模，这说明**局部语义比全局语义更吃数据量**，
    也说明这条线的 ×8 提升是在一个非常低的起点上取得的。

#### 读出层的意外：训练路径上的那一层**不是**读出最好的一层

`last` 在所有区域组上都高于 `penult`（+1.2 ~ +16.6），但在 `gt_base` / A′ 上反而更低
（−1.0 / −1.6）。也就是说：区域损失只压在倒数第二层，但它带来的空间结构
**传播到了最后一层**，而最后一层同时享有全图对比损失带来的"与文本空间对齐"，
两者叠加后读出更好。→ 训练侧的取层（FG-CLIP 取 `hidden_states[-2]`，理由是
"最后一层被全图损失污染"）在**训练**上大概率仍然对，但**评测**时不该跟着取倒数第二层。
本页两种读出都报，不做取舍。

**未做**：Context59 / ADE / COCO-Object / Cityscapes 五个口径（脚本只接了 VOC）；
ClearCLIP / SCLIP / NACLIP 式推理期改造作为对照（有意不做，见脚本头部口径声明第 4 条）；
噪声地板只有 n=2。

  本页目前只有**损失值占比**（W=2.0 时 68%、W=4.0 时约 81%，§5.7），从没量过
  **梯度范数占比**。这两个数不必相等：区域损失是 SigLIP 逐对口径、有效行数约 4340，
  主损失 4096，两者的 per-sample 尺度和 backbone 通路都不一样。
  必须量的理由来自 VISReg 线的一个反面教训：那条线实测 VISReg @1.83e-4
  对 backbone 的梯度范数 **2.94e-05**，对比损失 **1.43e+02** → 占比 **2.06e-07**，
  也就是**它此前跨 4 个数量级的所有权重/方向/目标形状扫描全部发生在死区里**，
  那些"无差异"结论因此都不构成有效排除（`scripts/tools/probe_grad_ratio.py`）。
  → 对本页：量一次能把"为什么 W 必须开这么大、大约会在哪里饱和"从经验曲线
  变成有原理的说法，也能在 W=8.0 起训前先预测它还有没有空间。
- ~~**⚠️ 评测维度上的空洞：`scripts/eval/` 里至今没有任何开放词表分割 / mIoU 入口**~~
  **✅ 已补（2026-08-27）**：`scripts/eval/eval_ovss.py` + VOC-2012 val 全量 1449 图，
  结果与四个结论见 **§5.8**。事后看，这条当时判断的"价值可能高于再扫一个权重"是对的 ——
  它没有加一个点，而是**把已有的权重结论限定住了**。剩下的三块：
  - **另外四个 benchmark**：Context59 / ADE / COCO-Object / Cityscapes（脚本只接了 VOC）。
    VOC-20 只有 20 类且都是常见物体，是这一族里最容易的一个，不足以代表整族。
  - **ClearCLIP / SCLIP / NACLIP 式推理期改造作为对照臂**（当前有意不做，
    见 `eval_ovss.py` 头部口径声明第 4 条）。它能回答"训练学到的空间结构和
    推理期救急改造是否互补"，也是与论文数字对齐的必要条件。
  - **噪声地板只有 n=2**（penult 0.12 / last 0.16），够用但很薄。

### 6.4 本页范围限制

- 只有 CC3M 一个规模（区域 TSV 286.9 万 / G 的 198.4 万），未做 scaling 验证。
- 区域框与短语来自 gemma 自动标注，非人工，质量上限未知
  （verdict 实验 §5.5 就是在探这个，结论是过滤收益不大）。
- 全部 `epoch_10` 单点，未做 epoch 选择的敏感性分析。
- Urban t2i 的 2σ 未单独定标，本页沿用 i2t 的 1.92 ——
  §5.7 里 W=0.5 的 Urban t2i +2.20 只有 1.1× 2σ，是全表最脆弱的一个"显著"判定
  （W=1.0 的 Urban 两项相对 W=0.5 都判噪声内，本身就受这个限制影响）。
- `region_weight` 只有 0.2 / 0.5 / 1.0 / 2.0 四点，**最优点仍未定**（五个非长文本口径
  到 2.0 仍在涨，图像塔口径的增量甚至在加速）。本页所有"更大的 W 更好"的说法都只是
  "2.0 好于 1.0 好于 0.5 好于 0.2"，不是"2.0 是最优"。W=4.0 在跑（§6.2）。
- **本页所有 run 都走 `tsv` 顺序遍历，比 `wds + resampled` 低约 0.6pt**
  （22.84 vs 历史锚点 23.44，出处 [[cc3m_text_dedup]]:196）。页内互相比较不受影响
  （全部同管线），但**与外部数字或论文数字比较时要记这个换算系数**，
  且"区域监督值 +N 点"里可能有一部分是从更弱的起点起跳的。
- **每个 W 点只有一次运行、一个 seed。** W=2.0 相对 W=1.0 的 +1.1~1.9 是 5.7~8.6 倍 2σ，
  远大于噪声地板，但那个 2σ 是 `gt_base` 系标定的，**未在高 `region_weight` 下重标** ——
  若高 W 下 run-to-run 涨落本身变大，这些倍数会被高估。这是本页最大的未验证前提。
- **OVSS（§5.8）的噪声地板只有 n=2**（`gt_base` 两个 seed，penult 差 0.12 / last 差 0.16），
  且同样是在 `gt_base` 上标的、未在高 W 下重标 —— 与上一条同一个限制。
  §5.8 里最小的那个差值（0.2→0.5 的 penult −1.10）是它的 7~9 倍，所以本页引用的
  OVSS 差值都不靠这个地板的精度吃饭，但"OVSS 上 W=0.2 与 W=0.5 谁更高"这种细分排序不可信。
- **OVSS 只做了 VOC-20 一个 benchmark、只做了 `epoch_10` 一个点、只有 `projective` 一个口径。**
